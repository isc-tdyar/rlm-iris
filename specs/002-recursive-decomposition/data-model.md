# Data model: Recursive decomposition

No persistent entity is added. What changes is the shape of three things already
in flight — the traversal frontier, a dimension spec, and a trace row's depth —
plus two new properties.

## Traversal frontier (in-memory, `RLM.Engine.Run` local)

| Field   | Type       | Meaning                                          |
| ------- | ---------- | ------------------------------------------------ |
| `path`  | `%String`  | Slice path in the existing grammar; `""` at root |
| `depth` | `%Integer` | Levels below the run's starting point, from 0    |

Held as `stack(n) = $ListBuild(path, depth)` with `n` counting down as slices pop.
Pushed in reverse declaration order so pop order is declaration order (research
decision 1).

`depth` counts from the run's starting point, so a scoped run's root is depth 0
even though its path has components. `$Length(path, "/")` is the grammar depth and
is what `MAXDEPTH` bounds; the two differ by the scope's length.

**Invariant**: a path is pushed only if `RLM.Slice.Resolve` accepted it. Names are
generated by `Expand` from the store's own children, so this holds by construction
and the resolve is a check rather than a filter.

## Dimension spec (existing `%DynamicObject` from `Source.Dimensions()`)

Unchanged in shape. A bucketed dimension produces the same object a categorical
one does:

```json
{
  "label": "reject_fraction",
  "children": [
    { "token": "clean", "label": "clean (<5% rejected)" },
    { "token": "moderate", "label": "moderate (5-20% rejected)" }
  ]
}
```

This is FR-009 stated as data: a policy reading this cannot tell which kind it is,
because there is nothing in it that says.

## Bucket declaration (new, `RLM.Source.Table` private state)

| Field         | Type      | Meaning                                       |
| ------------- | --------- | --------------------------------------------- |
| `dimension`   | `%String` | Token name, as for a categorical dimension    |
| `property`    | `%String` | Numeric property; validated against the class |
| `breakpoints` | `%List`   | Ascending, deduplicated, at least one         |

`n` breakpoints yield `n+1` children. Child `i` covers `[b(i-1), b(i))`, with the
first open below and the last open above. Tokens are ordinals (`b0`, `b1`, …) so
a token stays stable when a label is reworded; labels carry the range.

**Validation at declaration time**, not at peek time: a property that is not on
the class, an empty breakpoint list, or breakpoints out of order are refused by
`AddBucketedDimension` with a status. The same reasoning as `AddDimension`'s
existing property check — a bad dimension discovered at peek time makes a
configuration error look like a store failure.

## Predicate term encoding (existing, widened)

Private between `RLM.Source.Table.Predicate` and `.Peek`. Terms joined by
`$Char(1)`; fields within a term by `$Char(2)`.

| Before              | After                                  |
| ------------------- | -------------------------------------- |
| `property<C2>value` | `property<C2>=<C2>value`               |
| —                   | `property<C2>>=<C2>value` (bucket low) |
| —                   | `property<C2><<C2>value` (bucket high) |

`Peek` renders each term as `property <op> ?` and binds the value. A bucket
contributes one or two terms; every operator comes from this table and none from
outside the class.

## Trace row (existing, one field now varies)

`Add()`'s `depth` argument has always been written to field 2 and has always been
0 for decisions and 1 for sub-calls, because there was only ever one level. It now
carries the real depth. No field is added, no field changes position, and a
pre-feature reader reading field 2 gets a number that means what it always meant.

A decision row exists per decided slice rather than one per run, so
`RLM.Trace.Decisions()` returns as many decisions as slices decided. Its existing
`seqs` output already distinguishes them.

## New properties

- `RLM.Engine.MaxDepth` (`%Integer`, default 1) — today's behaviour, so
  recursion is opt-in (SC-002).
- `RLM.Engine.ReportStyle` (`%String`, default `"plain"`) — a passthrough,
  because the engine owns the report object.
- `RLM.Report.Style` (`%String`, default `"plain"`) — today's output stays
  byte-identical (SC-002).

`RLM.Source` gains no property. Readiness is a method with a default
implementation (`Ready(Output reason)` returning 1), so an existing source is
ready without being edited (FR-015).
